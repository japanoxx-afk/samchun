# samchun

삼국지 천명 2 (3KD2 1.20g) Windows 런처·패치 및 인게임 Internet 호환 서버.
게임 원본과 게임 데이터는 포함하지 않습니다.
지원 원본 SHA256: `A0EE96931B3B74FCE739062D8E58253892510EF863E9127648AC38FD4D515F99`.

## 1.3.5 인터넷 서버

게임의 원래 INTERNET → 회원가입/로그인 → 공용 대기실 → 방 생성 화면을 사용합니다.
런처에서 로그인하지 않습니다. 기존 직접 IP 우회 방식과 다른 서버입니다.
계정은 A의 호환 서버에 새로 가입하며 과거 공식 서비스 계정과 연동되지 않습니다.

실제 게임에서 회원가입, 로그인, 대기실 진입, 방 생성까지 확인했습니다.
프로토콜 테스트에서 두 클라이언트의 목록·채팅·방 참가·중계 전송을 확인했습니다.
**서로 다른 두 PC의 실제 게임 시작·전장 동기화는 아직 검증하지 않았습니다.**
길드·랭킹은 구현하지 않았습니다. 인게임에 해당 원본 메뉴가 남아 있습니다.

## A/B 설치 및 실행

Windows 10/11 64비트에서 ZIP 전체를 새 폴더에 풉니다. Python 설치는 필요 없습니다.
양쪽에 같은 버전의 게임 원본과 맵이 있어야 합니다.

1. A: launcher.exe에서 원본 3kd2.exe 경로 지정 → **인터넷 서버 구동**.
2. A: 서버 주소 `127.0.0.1` → **입력한 서버로 게임 접속** → 게임에서 **INTERNET**.
3. A: 게임에서 회원가입/로그인 → 대기실에서 방 생성.
4. B: 서버 주소에 A의 IPv4 입력 → **입력한 서버로 게임 접속** → 게임에서 **INTERNET**.
5. B: 자기 계정으로 회원가입/로그인 → 방 목록에서 A의 방 선택 → 참가.

B에서는 호환 서버를 별도로 켜지 않습니다. A의 서버 창을 닫으면 접속이 끊깁니다.
같은 LAN 또는 동일한 Radmin VPN/Hamachi 네트워크의 A 주소를 사용하세요.
서버 포트는 TCP **4800**(로그인/대기실), TCP **4901**(게임 중계)입니다.
방화벽을 통째로 끄지 말고 해당 서버 프로그램/포트만 허용합니다.
원본 인증 통신은 TLS가 없으므로 사설 LAN/VPN에서 사용하고 다른 서비스 암호를 재사용하지 마세요.
아이디 1자부터, 빈 암호도 허용합니다. 원본 패킷 용량인 ID 15바이트·암호 10바이트 상한은 유지합니다.
일반 게임 실행에서도 랠리 패치를 켜면 INTERNET 연결 패치를 적용합니다. 인터넷 접속 버튼은 항상 연결 패치를 적용합니다.

## 서버 데이터

기본 위치: `%LOCALAPPDATA%\SamchunServer`.
`accounts.sqlite3`에 무작위 salt와 PBKDF2-SHA256(600,000회) 검증값을 저장합니다.
암호 원문과 이메일은 저장하지 않습니다. 로그에는 패킷 종류/길이만 기록하며 암호·채팅 본문을 기록하지 않습니다.
계정 DB는 ZIP/저장소에 포함하지 않습니다. 서버를 옮길 때는 종료 후 DB를 별도로 옮기세요.
방과 접속 상태는 메모리에 보관하며 서버 재시작 시 초기화합니다.

직접 실행: `server/samchun-server.exe --bind 0.0.0.0 --port 4800 --relay-port 4901`.
원본 클라이언트는 기본 포트를 사용하므로 일반 사용자는 포트를 바꾸지 않습니다.

## 기존 패치

- 창모드, 출력 해상도, 16:9 늘림 (전장 시야 범위는 원본과 같음)
- 건물 우클릭 랠리, 기·오어 랠리 자동채집, 랠리 방향 생성
- Enter 입력창 수정, F2 군사 선택, 마침표 대기 일꾼 선택 (최대 32기)
- 원본 EXE 보존, 3kd2-modern.exe를 별도로 생성

32기 초과 선택, 복수 건물 동시생산, 순차 마법시전은 미구현입니다.
일반 **게임 실행**에는 호환 서버 연결 패치를 적용하지 않습니다.

## 업데이트

런처 업데이트 버튼은 GitHub의 최신 정식 릴리스에서 launcher.exe/SHA256.txt를 내려받아
해시와 어셈블리 버전을 검증하고 백업·교체·재시작합니다. 파일 선택창은 사용하지 않습니다.
1.3.12 정식 릴리스는 기존 런처의 업데이트 버튼으로 설치할 수 있습니다.
서버 EXE는 런처에 내장되며 서버 구동 시 `%LOCALAPPDATA%\SamchunServer\bin`에 검증 후 설치합니다.
그래픽 런타임을 포함한 신규 설치에는 전체 ZIP을 사용하세요. 두 PC 대전은 아직 실사용 검증 전입니다.
배포: https://github.com/japanoxx-afk/samchun/releases

## 개발 및 검증

- `build.ps1 [-OutputDirectory 경로] [-ServerExecutable 서버EXE경로]`: .NET Framework C# x86 런처 빌드 (서버를 먼저 빌드)
- `build-server.ps1 -Python python`: Python 3.12 + PyInstaller 6.22.3으로 서버 EXE 빌드
- `python server/compat_server.py --bind 127.0.0.1 --data verification/server-test`: 개발 서버
- `python tools/test_compat_server.py`: 네이티브 요청 기반 소켓 통합 테스트 (pefile/unicorn 필요)
- `python tools/test_compat_native.py`: 원본 로그인·가입 패킷 생성/성공 응답 파서 에뮬레이션
- `python tools/test_compat_room_native.py`: 원본 방 생성 응답의 중계 접속 인자 검증
- `python tools/test_compat_patch.py`: 성공/연결 실패 메뉴 경로와 스택/주소 패치 검증

검증 도구의 게임 경로는 로컬 설치에 맞게 조정하세요. 원본 패킷은 재배포하지 않습니다.
기존 랠리 바이너리 리소스는 assets/rally.bin이며 생성기는 tools/build_game_patch.py입니다.
네트워크 코드: src/CompatPatch.cs 및 server/compat_server.py.

## 계정 전적

1.3.4는 대전 종료 결과를 accounts.sqlite3의 match_results 테이블에 누적합니다.
기존 계정과 암호는 유지하며, 재로그인·서버 재시작 후에도 승패가 유지됩니다.
동일 경기·계정 결과는 한 번만 반영합니다. 게임의 기존 전적 조회 요청에 저장된 기록을 반환합니다.
원본이 결과 4(미집계)로 보내는 짧은 경기·중단·무효 결과는 승패에 포함하지 않습니다.
클라이언트의 원래 승패 판정을 사용하며 서버가 대전을 재연산해 판정하는 방식은 아닙니다.
이전 버전은 결과 내용을 저장하지 않아 과거 전적은 복구할 수 없습니다.
1.3.3의 TCP_NODELAY 응답속도 변경은 클라이언트와 서버 모두 롤백했습니다.
A·B 런처 업데이트와 게임 재실행, A 서버 재구동이 필요합니다.
검증: tools/test_stats_native.py, tools/test_compat_server.py.

## 방 재생성 및 진영 선택 수정 (1.3.5)

퇴장 요청은 원본이 응답을 소비하지 않으므로 서버도 응답을 보내지 않습니다.
이전 버전의 불필요한 퇴장 응답이 다음 방 생성 응답으로 오인되는 문제를 수정했습니다.
가입·로그인 성공 응답에 프로필 뒤 진영 마스크 7을 전송해 랜덤과 6개 진영이 표시됩니다.
기존 계정에도 재로그인하면 적용됩니다. A 서버를 반드시 새 버전으로 재구동하세요.

## 생산 유닛 초기 마나 (1.3.6)

새로 생산된 유닛의 마나를 최종 최대 마나의 65%로 설정합니다(소수점 버림). 일반 생산과 출구 배치 대체 경로에 모두 적용합니다. 기존 유닛과 저장된 마나는 변경하지 않습니다. 런처의 게임 패치를 켜고 게임을 재실행하세요. 인터넷 대전 참가자는 모두 1.3.6으로 업데이트해야 합니다.


## 64기 선택 및 순차 시전 (1.3.7)

선택 목록과 명령 버퍼를 확장해 드래그, F2 군사 선택, . 대기 일꾼 선택 및 부대 지정/호출이 최대 64기를 처리합니다. 인터넷 명령은 기존 32기 패킷 두 개로 나누어 전달합니다. 마법을 한 번 클릭하면 해당 마법을 사용할 수 있고 현재 마나가 충분한 한 기만 시전합니다. 다음 클릭은 이후의 시전 가능한 유닛으로 이어지며 끝에 도달하면 처음으로 돌아갑니다.

기존 저장 형식을 유지하므로 저장/불러오기 시 선택 목록과 부대 지정은 앞의 32기만 복원됩니다. 게임 내 유닛은 삭제되지 않습니다. 다시 64기를 선택/지정할 수 있습니다. 인터넷 대전의 양쪽 런처를 모두 업데이트하고 게임을 다시 실행하세요.

검증: `tools/test_selection_patch.py`에서 원본 선택·해제·부대·지면 명령·마법 생성 코드와 새 분할/순차 시전 코드, 기존 패킷 인코더 및 저장/불러오기를 x86 에뮬레이션으로 실행합니다. 두 PC 실제 대전 및 화면 조작 검증은 별도로 필요합니다.


## F2 선택 누락 수정 (1.3.9)

내부 이동 분류 값 대신 실제 유닛 ID 범위(1000~1499)로 군사 유닛을 판별합니다. 일꾼 3종과 원본 선택 제외 대상(0x468)은 제외합니다.

## 패치노트 및 생산건물 패치 제거 (1.3.10)

런처의 패치노트 버튼으로 개선 내역을 확인할 수 있습니다. 내역은 런처에 내장되어 별도 파일이나 인터넷 연결 없이 표시되며 업데이트와 함께 갱신됩니다. 창의 크기를 조절하고 스크롤할 수 있습니다.

1.3.8~1.3.9의 생산건물 복수 선택·동시 생산 변경은 제거했습니다. 건물 선택 제한, 생산 메뉴 및 생산 버튼은 원본 방식으로 돌아갑니다. 최대 64기 유닛 선택, F2 군사 선택, 쉬는 일꾼 선택 및 순차 마법 시전은 유지합니다. 게임을 종료하고 런처를 업데이트한 뒤 다시 실행하면 원본 EXE에서 제거 사항을 반영한 실행 파일을 새로 생성합니다.

## 우클릭 랠리 효과음 (1.3.11)

땅 또는 자원 우클릭으로 랠리를 지정할 때 수동 랠리와 같은 원본 효과음(461)을 한 번 재생합니다. 실제 우클릭 명령 전달 지점만 변경하므로 커서 미리보기, 일반 이동·공격, 수동 랠리 및 다른 플레이어의 명령에는 추가 효과음을 재생하지 않습니다. 게임의 음소거 설정을 따릅니다.

## 우클릭 랠리 표시 효과 (1.3.12)

실제 우클릭 랠리 명령 전달 때 수동 지정의 원본 녹색 동그라미 효과를 같은 클릭 위치에 한 번 표시합니다. 원본 표시 객체(0x36f6), 좌표 변환 및 표시 함수를 재사용합니다. 효과음과 다른 기능을 유지하며 커서 미리보기와 일반 유닛 명령에는 추가 효과를 표시하지 않습니다.
